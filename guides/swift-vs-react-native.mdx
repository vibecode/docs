**Choose Swift if your app is for iPhone and iPad only and you want the most native look, feel, and access to Apple features. Choose React Native if you need the same app on iPhone and Android from one codebase.** Swift (with SwiftUI) is Apple's own language for Apple devices. React Native is Meta's framework that writes the app in JavaScript or TypeScript and renders real native components on both iOS and Android. In Vibecode you don't write either one: pick **iOS app** for Swift or **Mobile app** for React Native when you create a project, and the agent writes the code.

## Swift vs React Native at a Glance

| | Swift (SwiftUI) | React Native (Expo) |
|---|---|---|
| **Made by** | Apple | Meta, with Expo's tools and cloud services |
| **Language** | Swift | JavaScript or TypeScript |
| **Runs on** | iPhone, iPad, and other Apple devices | iPhone and Android (plus web) |
| **UI** | Apple's native SwiftUI components | Native components on each platform, driven by JavaScript |
| **Look and feel** | Exactly like Apple's own apps | Native, but cross-platform code can feel less "iOS" unless tuned |
| **New Apple features** | Available as soon as Apple ships them | Available once a library or native module supports them |
| **Android** | No | Yes, same codebase |
| **Build tools** | Xcode on macOS | Expo (EAS) or Xcode and Android Studio |
| **Best for** | iPhone-first products, polished consumer apps, games, apps that lean on Apple features | Apps that must reach both iPhone and Android users |

## When to Choose Swift

- **Your users are on iPhone.** Many consumer, productivity, and paid-subscription apps start on iPhone only.
- **You want it to feel like an Apple app.** SwiftUI uses Apple's own controls, navigation, and animations.
- **You'll use Apple features.** Things Apple adds to iOS show up in Swift first.
- **You're making a game or something visual.** Swift gives the agent direct access to Apple's graphics and animation frameworks.
- **You want to build for iPhone Duo.** Vibecode previews iOS apps on the foldable iPhone Duo as well as iPhone.

## When to Choose React Native

- **You need Android too.** One codebase reaches iPhone and Android users.
- **You want to share a link.** Testers can open a Mobile app from a share link without an App Store release.
- **You're selling subscriptions today.** The guided RevenueCat setup and the App Store Preflight check are built for Mobile app projects.
- **Your team knows JavaScript.** If you'll edit the code yourself later, TypeScript may be familiar.

Still unsure? If you only care about iPhone, start with Swift. If losing Android users would hurt, start with React Native.

## Is React Native "Native"?

Mostly. React Native doesn't run your app in a web view: it draws real iOS and Android components, controlled by JavaScript. Apps feel native for most uses. The differences show up in platform-specific details (navigation patterns, the newest Apple APIs, heavy animation), where Swift has direct access and React Native relies on libraries. A website wrapped in an app shell is different again, and Apple often rejects those. See [How to Turn a Website Into an App](/getting-started/web-to-mobile).

    Neither is better for every app. Swift is better for iPhone-only apps that should feel fully native and use Apple features. React Native is better when you need one app for iPhone and Android.

  <Accordion title="Can a Swift app run on Android?">
    No. Swift apps run on Apple devices. For Android, build a React Native (**Mobile app**) project.
